# Compiler outcome classification defect

Independent review of SpecGraph PR #830 at head `86c8ead0a6484ab394b58bdc4da607c90dea421e` found that `capture_ontology_snapshot` classified every `subprocess.CalledProcessError` as `invalid`. A nonzero exit or signal does not establish that the selected package is invalid. The local Ontology checkout at `b8516d0bc3154f8309ec4fc28f9d29a05a6a692c` provides a concrete counterexample: `Sources/OntologyC/main.swift` uses exit 1 in `compile` both for compiler diagnostics and for thrown errors. This source observation does not authenticate an operator's selected compiler or prove a particular production failure.

SG-SPEC-0072's verification contract reserves `invalid` for detected invalidity and uses `unavailable` for a missing required check. SG-RFC-0232's `ONT-INPUTS` and `ONT-TRUST` provide the related source-attributed intent. An ambiguous compiler failure must therefore remain unavailable; independently detected pin and source/IR mismatches remain invalid. The coordinating agent chose this conservative classification during the delegated review; it also applies to undecodable process output. This decision is not a human approval. This repair does not parse stderr to infer a policy outcome, change Ontology's compiler, approve semantic meaning or activate a gate.

The root cause was an unsafe assumption that a process exit establishes an input diagnosis. The regression fixtures exercise check failure, compile failure after a successful check, signal termination, undecodable output, independently detected mismatches, missing-input and compiler-failure precedence, and captured input reuse. [defect.json](defect.json) records the bounded observation and [verification.json](verification.json) records actual checks. The prepared fix is review-pending; a merged revision is separate closure evidence. Graph routing uses the existing intent and proposal lanes, without a new canonical kind or numbered proposal.

The [graph return path](graph-links.json) connects the source, defect and verification through UserIntent → OperatorRequest → Proposal to SG-SPEC-0072. The authored proposal is not owned by the derived queue; its next action is review of the prepared correction and regression evidence.
