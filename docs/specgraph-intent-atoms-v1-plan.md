# SpecGraph Intent Atoms v1 и исторический replay

## Цель

Создать воспроизводимый профиль извлечения Intent Atoms из спецификаций SpecGraph и проверить его на истории проекта. Профиль — конкретный выбор реализации SIB, без изменения общего определения фреймворка.

Первый этап охватывает **acceptance criteria и явно объявленные intent atoms**. Результат — проверяемые snapshots, структурные diffs и ограниченный replay истории, подготовленные для последующего вычисления SIB_FULL.

## 1. Контракт атомизации

- Идентификатор профиля: `specgraph-intent-atoms-v1`.
- Поддержать текущие плоские спецификации и документированный envelope: `acceptance[]` / `spec.acceptance[]`, `atoms.intents[]` / `spec.atoms.intents[]`.
- Если у узла объявлен `atoms.intents`, использовать его как явное представление атомов; acceptance сохранять как контекст, повторно не считать. Пустой список означает ноль явных атомов; некорректный список — ошибку измерения, без скрытого fallback.
- Если явные атомы отсутствуют, каждый непустой строковый acceptance criterion считать одним атомом. Составные предложения автоматически не дробить.
- Цели, premises, rationale, evidence, ссылки, metadata и прочие смысловые поля не включать в этот профиль. В отчёте явно обозначить ограниченное покрытие.
- Считать объявления атомов, без семантической дедупликации между спеками. Повторы отмечать диагностикой, не удалять.
- Сохранять status и provenance узла как атрибуты наблюдения. Не приравнивать наличие атома к человеческому авторству, одобрению или верифицированности.

Определение профиля и примеры разместить в SpecGraph; Metrics оставить владельцем общей методологии SIB.

## 2. Snapshot и diff

Добавить отдельный read-only инструмент под `tools` с операциями `snapshot`, `diff` и `replay`.

**Вход:** путь к Git-репозиторию, точные revisions, корень спецификаций — по умолчанию `specs/nodes`. Читать tracked YAML непосредственно из Git, без checkout и запуска исторического кода.

**Snapshot JSON должен содержать:**

- commit SHA, версию и digest профиля, версию анализатора, область сканирования;
- атомы с node ID, исходным полем, адресом элемента, текстом и доступным явным ID;
- количества по узлам и способам извлечения;
- диагностические сообщения и статус полноты измерения.

Нормализовать окончания строк и внешние пробелы. Форматирование YAML и порядок ключей не должны менять результат; внутреннее содержание строк сохранять.

**Правила diff:**

- Явные атомы сопоставлять по паре `node ID + atom ID`; изменение текста считать `modified`.
- Acceptance без ID сопоставлять внутри узла по нормализованному тексту с учётом повторов. Перестановка списка не меняет состав.
- Изменение текста acceptance без ID показывать как удаление и добавление: не угадывать сохранение идентичности.
- Перенос файла при неизменном node ID не менять идентичность узла.
- Межузловые переносы, splits/merges и семантические переформулировки автоматически не устанавливать.
- Смену способа извлечения обозначать отдельной диагностикой: её нельзя молча интерпретировать как рост или потерю Intent.

При ошибках YAML, конфликтующих ID или неподдерживаемом формате сохранять доступные наблюдения, но помечать общий результат как неполный. Частичный subtotal не выдавать за полный `N_spec`.

## 3. Ограниченный исторический replay

- Зафиксировать локальный `main` полным SHA и взять последние **30 последовательных first-parent состояний**, включая commits без изменений спецификаций; если история короче — все доступные.
- Записать SHA выбранных checkpoints в manifest. Связи с PR в первом этапе необязательны.
- Одной версией анализатора построить snapshot каждого состояния и diff соседних состояний.
- Сохранять артефакты раздельно по SHA; читать только данные соответствующего commit.
- Неподдерживаемые исторические форматы отмечать как пробелы, не преобразовывать молча современной схемой.
- Подготовить сводку динамики количества атомов, добавлений/удалений, полноты извлечения и смен представления.

На этом этапе проверяем формальный подсчёт Intent. Полный SIB, экономические показатели, причинные выводы о дефектах и LLM-классификацию не добавляем.

## 4. Интеграция и совместимость

В существующем metric-pack adapter уже используется proxy `intent_atoms → acceptance[]`. Добавить новый versioned snapshot как опциональный источник с явной provenance; существующий proxy сохранить и обозначить как legacy.

Отсутствие нового артефакта не должно менять прежние отчёты или gates. Несовпадение revision/profile делает артефакт непригодным для текущего измерения.

UI SpecSpace в этом этапе не менять. Передачу нового snapshot в панели выполнить следующим отдельным этапом после проверки контракта.

## 5. Проверки и критерии готовности

- Fixtures для обоих форматов узлов, acceptance, явных атомов, пустых списков, повторов и некорректных данных.
- Проверки неизменности результата при форматировании YAML, перестановке acceptance и переносе файла.
- Проверки изменения явного атома, удаления/добавления acceptance и смены представления.
- Golden snapshots и diffs с вручную проверенными ожидаемыми значениями.
- Повторный replay того же manifest даёт идентичные данные измерений; служебное время запуска сравнивается отдельно.
- Регрессии существующего metric-pack adapter, профильные тесты и обязательные CI-проверки SpecGraph проходят.

Поставить двумя последовательными PR: **контракт и snapshot**, затем **diff, replay и опциональный adapter**. Каждый PR включает документацию и проверяемые примеры.

Следующий этап после приёмки — подключить проверенный ряд Intent snapshots к выбранным формулам SIB_FULL и сопоставить его с историей реализации.
